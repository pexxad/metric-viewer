# 概要

時系列データをグラフ表示するWebアプリケーション。  
1つのデータセットはタイトル(下記2要素)とその表データからなる。

- データID
- データ名(Optional)

表データは、1列目に属性名の一覧、2列目以降に各属性のデータを持つ一般的な二次元のデータである。  
ただし、いくつかデータセットの特徴・制約がある。

- 時系列データとして扱う都合上、1列目は必ず時刻とする
- 一部のセルが欠けていることがありうる

## データセットの例

日本の個別株の日次データをイメージすると、タイトルは以下の2つとなる。

- 銘柄コード
- 銘柄名

それに付随する表データは下記である。

|time|株価|出来高|
|-|-|-|
|2026-03-22T15:30:00|1000|200|
|2026-03-23T15:30:00|1050|150|
|2026-03-24T15:30:00|1120|300|

## 画面イメージ

画面イメージは以下の通り。

- データセットのパネルを追加するボタンがある
- 各パネルはデータID、データ名、属性名、パネル削除ボタンを持つ
- グラフの色とパネルの色が対応している
- 分析的な利用もできるように、任意個数のグラフを重ね合わせられる
- グラフをマウスホバーすると値が表示される
- グラフの下にスクロールバーがあり、過去に遡れる
- グラフの形式はスムージングありの折れ線グラフを想定。他のグラフ種別は将来的に実装する
- その他グラフ要素諸々のクオリティはTradingViewを参考にする

## 技術仕様

- ReactとNodeJSのフレームワークで完結する実装
- Cognito認証を通してバックエンドAPIのトークンも取得する
    - どのアカウントで認証したかによって、バックエンドAPIの認可の範囲も制御される想定
- データはローカルに置いたCSVファイル、またはAPIで取得する
    - APIで取得するパターンは、プラグイン的に対応APIを追加できるようにする
    - APIのアクセスキー、シークレット、トークンなどの管理はセキュリティに注意する
- グラフ表示やAPIクライアントなど、疎結合にできる部分は積極的に疎にする

## 作業時の注意事項

- rmなどの間違ったときのリスクが大きい操作はユーザに依頼する
- 対話プロンプトが出るコマンドはユーザに依頼する
- コンテキストがcompactionされるときに備えて、仕様書や作業ログを随時、詳細に書き出す

## グラフ描画およびLightweight Charts v5を使うときの注意点

- TradingViewのロゴを消す
- スムージングをかける
- データの点が折れ線に隠れないように強調する
